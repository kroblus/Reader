## Implementation

- Preview: one cancellable job/version, URL/version checked before success/error publication, immediately invalidated on URL edit or route exit. Only URL is SavedStateHandle state. Public flows are read-only. Confirmation sets submitting synchronously, preserves input/preview on creation failure, and exposes a separate submission failure.
- Task creation: a DAO transaction both reuses matching tasks and writes task/chapters. Room serializes concurrent transaction creation; app button disabling is not the persistence guarantee. Scheduling follows commit; startup reconcile repairs missing schedule and orphaned DOWNLOADING work.
- Chapter identity: scheme/host case normalization and fragment removal only; path/query case, slash and query ordering remain meaningful. Nonempty source URL dominates title. Legacy no-URL chapters retain title fallback. Discovery and commit use the same function.
- Downloads: all HTTP output goes under `downloads/<taskId>/chapters`; execution-generation filenames avoid collisions. Final immutable files are prepared with fsync in the target book directory. Prepared files survive database failures for retry. A guarded DAO transaction rechecks target/task/generation, deduplicates against current chapters, assigns order, inserts chapters, recomputes statistics, invalidates search and marks the task complete.
- Progress uses a narrow lastReadAt update. Delete-book removes every append task. Task deletion removes only task-owned, currently unreferenced content; deleting a completed refresh preserves original and appended body files.
- Schema 8→9 adds `executionGeneration` (default 0), `executionOwner` (nullable WorkRequest UUID), `notBeforeMillis` and `automaticRetryCount` (default 0). Pause/resume/cancel and queued continuations advance generation. Same-owner WorkManager restarts advance generation before resuming; retry delay/count survive the database-to-scheduler interruption window. Worker claim, per-chapter updates, batch updates and final commit are conditional on generation plus permitted state. A deleted task cannot publish content.
- Notification action is explicitly Pause and calls the same repository operation as the app through a nonexported receiver. New generation WorkManager chains avoid KEEP racing with cancel of the previous generation; legacy unique work names are also canceled.
- Production batches remain eight chapters with a seven-minute ceiling and inter-request pacing. The test-only run-to-completion path was removed. Permanent HTTP errors become FAILED; retryable errors use bounded delayed WorkManager continuations and honor Retry-After.
