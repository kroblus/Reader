# 0.3.6 release recovery

The initial release run [43493157257](https://github.com/kroblus/Reader/actions/runs/43493157257)
checked `49f9d653de4a2c9e03f691eb0561b8dc3eb56231`. Compilation, JVM tests and lint
passed; the API 35 suite completed 120 tests with 2 failures and no skips. Signing and
publication were correctly blocked.

## Causes and changes

- `SearchLifecycleInstrumentedTest.kt:132` timed out **before searching**. It required
  three pages from a 1,795-character origin chapter. The default typeface and layout
  changed in 0.3.6; pagination itself completed in 330 ms. Give this test a longer
  origin chapter, retain the page-count check, and explicitly require a non-zero
  origin offset. The 131 search matches, result pagination/list restoration, activity
  recreation and exact persisted character-anchor assertions remain intact.
- The file-picker import logged a successful import in 223 ms, but its failure
  screenshot still displayed the modal “Reading file…” progress window. The probe
  saw the QA package owning input focus while the underlying Activity had none.
  Wall-clock polling did not advance Compose's test clock after the asynchronous
  import completed. Synchronize Compose on each probe iteration so the dialog can
  dismiss. Keep the resumed/attached/visible/Activity-focus/window-package checks,
  and also assert the imported book is visibly present on the shelf.

No production UI, default typography, application version, signing identity, test
exclusions or timeout limits are changed by these fixes.

## Safe retry of an unpublished tag

Run **Signed Android release** on the repair branch. Leave `recover_tag_object`
empty for validation and signed-artifact generation only. To recover an unpublished
version, supply the exact current Git tag-object SHA (not its peeled commit SHA).
For the original failed 0.3.6 attempt this was
`3f58c9bc002432fbd3e913a22382673b6cc1a161`.

Only after the same source passes the full quality workflow and signed-APK checks,
the recovery step verifies that no release exists, that the failed tag is unchanged,
and that its commit is an ancestor of the checked source. It moves the annotated tag
using an exact force-with-lease and verifies the resulting remote object before
publication. Existing releases (including drafts), changed tags, unrelated history,
authentication errors and non-404 API failures stop recovery. Existing push-tag
publication and ordinary manual build behavior remain available.

Local recovery-script failure-path checks and certificate parser tests pass. The
repair's Android validation is recorded in its own GitHub workflow run; the initial
failed run is retained as evidence and is not treated as successful validation.
